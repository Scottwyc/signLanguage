## 2. 数据库构建

### 2.1 加权特征数据库（v2.0）

- 路径：`手语宇宙_21词语义加权DTW数据库_v2.0_扩充数据候选_20260805`
- 每词 `features/` 帧特征按 **7 个局部语义组**拆分：| 组                                 | 维度  | 语义                      |
  | ---------------------------------- | ----- | ------------------------- |
  | pose                               | 27    | 身体姿态（9 核心点 × 3） |
  | left_hand / right_hand             | 63×2 | 双手位置（21 点 × 3）    |
  | left_hand_shape / right_hand_shape | 20×2 | 双手手形（几何特征）      |
  | face                               | 36    | 面部核心（12 点 × 3）    |
  | two_hand_relation                  | 8     | 双手关系                  |

### 2.2 语义权重库（21 词 profile）

- 源：`demo21_semantic_profiles_20260805/demo21_semantic_weights_v2_semantic_patch_20260805.json`
- 每词含：`group_weights`（各组权重）、`focus_groups`、`semantic_dtw`（53 个配置键：anchor_phases / 各 guard / score_scale 等）、`semantic_notes`
- 校准版本：`union_v3_calibration_all21_final_20260808/calibrated_profile_candidates.json`（判别力权重候选）

### 2.3 判别力权重（层 2，数据驱动）

- 脚本：`estimate_union_group_weights.py`
- 公式（按志愿者留一）：`sep(g) = (跨词平均组距离 − 同词平均组距离) / 同词组距离标准差`
- 数值稳定：std 下限（`max(std, 0.05·mean)`）+ sep clamp [-3, 3]
- 组权重 = softmax(max(sep,0))；与 base 的 blend（50/70）作为校准候选

### 2.4 前端模板（v2，每词 6 模板）

- 脚本：`build_frontend_templates_v2.py`
- 模板源：**仅可靠样本**（answer=1），**按用户轮询分散**（01/03/04/06/07 全可靠优先，02/05/08/09 过滤后补充，10/11 排除），每词 6 个
- 模板内容：237 维特征（pose 27 + 手 63×2 + 手形 20×2 + face 36 + 关系 8）+ profile + envelope + group_envelope
- **envelope**（总体）：每词正样本距离 q50/q90（包络软化用）
- **group_envelope**（各组）：每词各组正样本距离 q50/q90（局部语义评分参考）——多进程（10 workers）计算
- 输出：`apps/web/assets/content/scoring_templates_v2.json`

### 2.5 包络计算过程（含示例）

**总体 envelope（envelope）**——每词的"合理动作差异范围"：
1. 对每个**可靠正样本**（answer=1，模板外用户），分别与每词 6 个模板做 DTW，取**距离最小的模板**的 `dtw_distance`
2. 收集该词全部正样本的距离集合 D
3. 求分位数：`q50 = D 的第 50 百分位`、`q90 = D 的第 90 百分位`（线性插值）

**示例（花，2026-08-09 前端交叉验证数据）**：D ≈ {0.174, 0.186, 0.197, 0.206, …, 0.258, 0.266} → `envelope = {"q50": 0.2064, "q90": 0.2658}`。含义：花词"做得不错"的正样本，其模板距离中位数约 0.21，90% 在 0.27 以内；超出 0.27 视为偏离标准动作。

**group_envelope（各组局部）**——每组局部特征的"合理差异范围"：
1. 对每个正样本与最优模板，取 DTW 结果的 `group_mean_distance`（各局部组的加权距离）
2. 每组收集全部正样本的距离，求 q50/q90（**组内独立**，跨组尺度不同不影响）

**示例（花，用户04-07 正视角 4 个正样本 vs 用户01 模板）**：

| 局部组 | 4 个样本的组距离 | q50 | q90 |
|---|---|---|---|
| pose 姿态 | 0.254, 0.275, 0.279, 0.306 | 0.279 | 0.306 |
| left_hand 左手 | 0.041, 0.042, 0.064, 0.072 | 0.064 | 0.072 |
| right_hand 右手 | 0.008, 0.016, 0.018, 0.022 | 0.018 | 0.022 |
| left_hand_shape 左手形 | 0.057, 0.079, 0.091, 0.169 | 0.091 | 0.169 |
| right_hand_shape 右手形 | 0.015, 0.020, 0.021, 0.056 | 0.021 | 0.056 |
| left_hand_motion 左手过程 | 0.838, 0.951, 1.031, 1.042 | 1.031 | 1.042 |
| right_hand_motion 右手过程 | 0.000, 0.031, 0.073, 0.140 | 0.073 | 0.140 |
| left_hand_shape_motion 左手形变化 | 0.963, 1.037, 1.061, 1.077 | 1.061 | 1.077 |
| right_hand_shape_motion 右手形变化 | 0.000, 0.034, 0.066, 0.193 | 0.066 | 0.193 |
| two_hand_relation_motion 双手配合过程 | 0.000, 0.012, 0.085, 0.129 | 0.085 | 0.129 |

读法：花词核心语义聚焦右手（right_hand 0.018-0.022、right_hand_shape 0.021-0.056 距离小=做得好且一致），左手（left_hand_shape 0.057-0.169 距离大=左手形个体差异大，不做主要判别）；动态组（motion）尺度大于静态组（方向性归一化），但**组内独立包络保证评分可比**。face 全 0 且 q90=q50 → 不满足 `q90 > q50` → 该组不进 envelope（无判别信息，权重自然为 0）。

**软化示例（总体距离）**：若某查询花词得到 `aggregated_distance = 0.300`：
- `soften(0.300)`：0.300 > q90(0.2658)，超出包络 → `d' = 0.35×q50 + 0.5×(q90−q50) + (0.300−q90) = 0.0722 + 0.0297 + 0.0342 = 0.1361`
- 再算 `z = (0.1361 − softBase) / (softQ90 − softBase)`，其中 `softBase = 0.35×0.2064 = 0.0722`、`softQ90 = 0.0722 + 0.5×(0.2658−0.2064) = 0.1019` → `z = (0.1361−0.0722)/(0.1019−0.0722) = 2.15` → 分数 `= 80 − 35×(2.15−1) = 39.8` 分（明显偏离，需针对性练习）

**局部评分示例（right_hand_shape 右手形）**：若查询该组距离 `d = 0.050`：
- `z = (0.050 − q50 0.021) / (q90 0.056 − q50 0.021) = 0.83` → `localScore = 100 − 25×0.83 = 79.3` 分（接近合格线 80，提示右手形略有偏差）
- 若 `d = 0.070`（超 q90）：`z = (0.070−0.021)/0.035 = 1.4` → `localScore = 75 − 35×0.4 = 61` 分 → **标记 weak**，生成建议"「右手手形」做偏了…"

## 3. 打分算法（"并集"思路三层）

依据 `semantic_anchor_mapping_union_framework_20260805.md`：**"扩大正确范围应当扩大'有效语义实现方式的并集'，而不是直接放松所有距离阈值。"**

### 3.1 层 1 — 模板并集（参考侧）

- 每词 6 个多用户模板（覆盖不同动作风格）
- 评分距离 = 各模板距离取**最小 top-2 截尾均值**（避免单模板偶然近邻放行）

### 3.2 层 2 — 判别力权重 + 动态过程特征（局部加权）

- **静态局部组**：pose / left_hand / right_hand / left_hand_shape / right_hand_shape / face / two_hand_relation
- **动态过程组（帧序列特征，v1.1 开启）**：left_hand_motion / right_hand_motion / left_hand_shape_motion / right_hand_shape_motion / two_hand_relation_motion
  - 表达帧序列的动态过程（如"手部打开"是从闭合到张开的**过程**，而非静态帧的手形）
  - 生成：`_sequence_with_relative_motion_features`（相邻帧差分 + 方向性归一化）
  - 开关：`semantic_dtw.relative_motion_enabled`（v4 profile 21 词全部 True）；权重 `relative_motion_weight` × 对应静态组权重
- 局部距离 = DTW 路径上各组加权距离（`group_mean`，含帧权重 + missing 惩罚）
- **核心组过滤（v2.0）**：局部评分只针对该词 `focus_groups`（21 词齐全）声明的核心语义组——非核心组（如谗的左手/姿态，权重≈0 不影响总分）不显示分数、不判 weak、不生成建议，避免"总分 100 却显示一堆非核心低分"的视觉矛盾
- 局部评分 = 各组距离相对 `group_envelope`（q50/q90）映射：
  ```
  z_g = (d_g − q50_g) / (q90_g − q50_g)
  localScore_g = z ≤ 0 ? 100 : z ≤ 1 ? 100 − 25z : 75 − 35(z−1)
  ```
- **核心组加权评分**（group_composite_score）= `Σ w_g · localScore_g / Σ w_g`（w_g = 判别力 group_weights + motion 动态权重）——核心语义所需的局部（含动态过程）做对程度加权合成

### 3.3 层 3 — 包络软化（距离容差）

- 总体距离软化：`softenDistance(q50, q90, inside=0.35, ramp=0.5)`
  - d ≤ q50 → ×0.35（并集内自然差异，罚轻）
  - q50→q90 → 斜率 0.5
  - > q90 → 全罚
    >
- **answer=3 错位负例与跨词难负例不软化**（关键：避免误放）

### 3.4 分数映射与总分-局部联动

- 总体包络线性映射（保证通过线 80 有意义）：
  ```
  z = (softened − softBase) / (softQ90 − softBase)
  baseScore = z ≤ 1 ? 100 − 20z : 80 − 35(z−1)
  ```
  - `softBase = 0.35·q50`、`softQ90 = 0.35·q50 + 0.5·(q90−q50)`
- 无包络回退 `100·exp(−d/scale)`（scale=0.12）——**envelope 缺失时分数严重偏低（约 6-30 分），打包必须回填**（见 2.4 节 `--fill-envelope-from`）
- **总分-局部联动（v2.0，消除虚高）**：
  ```
  prototypeScore = min(baseScore, group_composite_score)
  ```
  - 核心组严重做错（如超市 right_hand 0 分）→ group_composite 低 → 总分明显降低（77 → ~63），不再"核心局部全错却接近通过线"
  - 难例（跨词动作各组都落在包络内）→ group_composite 偏高，但 baseScore（总体距离）已低 → min 取低
  - **交叉验证判定基于距离阈值（与分数映射无关）**，该联动不改变 21/21 判别结果，仅修正用户可见分数的合理性

### 3.5 语义阶段评分（时间维度，辅助）

- 按 `ordered_sequence` 段数等分 phase [0,1]，DTW 路径按模板帧 phase 分组聚合距离
- 阶段分 = `100·(2 − ratio)`，`ratio = 阶段距离/总距离`，`ratio>1.2` 标记弱阶段

### 3.6 针对性指导建议

- **局部建议**（弱组 localScore<80）：如"「右手手形」做偏了，请对照示范视频重点练习"
- **阶段建议**（弱阶段）：使用 `interactive_learning_contracts.json` 的 `ordered_sequence[].detail` 文案

### 3.7 语义阶段完整性门控（G1，v2.2 新增）

- **定位**：总分计算前的硬性门控——缺核心语义阶段（"几乎完全未覆盖"/序列截断）→ 分数封顶 60 + 明确提示
- **信号**：
  - `cov[k]` 阶段覆盖率（DTW 路径上标准阶段 k 帧映射到的查询独特帧数 / 标准阶段 k 帧数），动态阶段 `cov < 0.15` → 缺失
  - `stage_distances[k]` 阶段距离超 `1.6×` 全局均值且 `> 0.08` → 缺失
  - **时长完整性门**：查询/标准长度比 `< 0.6` → 序列截断（缺后半阶段，如"花"只做含苞不张开），仅**多阶段词**启用（单阶段词无"后半"概念，谗等短动作正样本帧数少避免误伤）
  - 动静判定用相对阈值（阶段 motion > 该词中位数 0.5× 才算动态；静态准备阶段不触发 cov）
- **阈值来源**：930 条 trusted_positive 全量校准（`calibrate_stage_gate_20260809.py`），正样本误伤 ~7%（保守硬门）
- **花词张开检测**：`flowerOpeningGuard`（Python `_flower_opening_guard` 的 JS 移植）——hand_shape spread 特征（用户无关），guard 不通过 → 不享受 core_visible_scale 提分
- **前端配置**：`apps/web/assets/content/stage_gate_config_20260809.json`（cov=0.15 / 时长门 0.6（多阶段词）/ shape 禁用 / cap=60）
- **已知边界**：通用目标形态检测（shape）尝试 5 版后因跨用户信号不可靠默认禁用；② 高维判别（查询 vs 目标词 38 维特征二分类，离线平均 AUC 0.888）因 JS/Python 特征口径未对齐暂未集成前端（保留离线评估工具与前端配置，待对齐后启用）

### 3.8 老算法 vs 轻量模型打分——范式对比结论（v2.2 追加）

**实测**（930 正 + 71 条人审错位负样本，完整报告 `/data/WYC/signLanguage/work/reports/dtw_vs_model_comparison_20260809.md`，5 图内嵌）：

| 指标 | 老算法 DTW+G1 | 模型 composite（conf 关闭） | 模型 ×conf（强门控） |
|---|---|---|---|
| 正均分 | 76.6 | 87.8 | 87.3 |
| 负均分 | 59.1 | 86.8 | 46.4 |
| AUC | 0.648 | 0.536 | **0.749** |
| 负拦截(<60) | 38.0% | 0.0% | **46.5%** |
| 正通过(≥80) | 58.4% | 84.6% | 82.2% |

**老算法上限的结构性原因**：①1D 距离压缩丢结构（阈值天花板）②模板稀疏（6 采样点 vs 11 用户分布）③手工特征/权重次优（face 6.9% 判别力仍占权重）④零学习机制（边界人工定义；21 词分类 95.6% 证明特征够但边界没学）⑤门控穷举覆盖不了连续错误空间 ⑥跨用户形态差异未建模。

**模型能突破的原因**：①学习判别表示（骨干 98.11% 预训练）②非线性时序建模（LSTM 语义而非逐帧距离）③学"程度"不依赖模板采样 ④47 动作头学习覆盖错误空间 ⑤词身份+动作程度双正交维度（conf×composite）⑥VL 语义知识注入 ⑦1.19M 参数容量。模型代价：需 VL 标注/预训练、composite 无负样本校准（必须配 conf 门控）、黑盒可解释性弱。

**最终架构**：模型主打分（total=composite×conf，AUC 0.749）+ G1 规则兜底硬检查（手部入画/时长完整性/花 guard）——模型给"程度与身份"，规则给"结构硬检查"，互补组合。

### 4.1 交互流程（v2.0 最终形态）
1. 互动学习选词 → 参考区（示意动画/参考视频 + 播放）+ 动作指导区（语义阶段/同时特征）+ 摄像头练习区（第三列）
2. **摄像头区只有一个 🎥 Record 按钮**：点击 → 倒计时 → 采集（3s × 10fps = 30 帧，720p 本地关键点）→ **自动评分**
3. 结果面板：**分数 → 针对性建议（chips 弱组+分数 → 一段去重合并建议）→ 局部语义评分（核心组分数条）→ ↻ 重新评分 / → 下一个**
4. 语言默认英文、主题默认日光（可切换）；切换语言不重置摄像头区（ensureCamera 恢复预览）

### 4.2 前端语义局部打分与总分的关联（核心逻辑）
1. **局部距离**：DTW 路径上各组加权距离（`group_mean`），多模板 top-2 平均
2. **局部评分**：每组距离相对该词 `group_envelope`（正样本组距离 q50/q90）映射为 0-100；**只计算 focus_groups 核心组**
3. **核心组加权评分** `group_composite_score` = `Σ w_g·localScore_g / Σ w_g`
4. **总分** = `min(总体包络线性分, group_composite_score)` —— 核心组做错 → 总分联动下降
5. **建议生成**：weak 核心组（<80）→ 映射到该词具体语义阶段（`ordered_sequence` 的 label/detail，关键词匹配）→ chips 展示弱组+分数 + 一段去重合并建议
6. 展示：总分与局部评分一致（核心组全对 → 高分+无建议；核心组做错 → 总分降 + 针对性建议）

## 7. 权重超参数优化规划（未来方向）

基于有效数据（受信任正样本 930 + 人工负例 71 + 模板外用户），把算法中所有权重超参数的系统性优化建模为**有约束的优化问题**。当前已有"粗糙数据驱动"（判别力权重 + 14 种网格候选 + 手工软化参数），需升级为全局优化。

### 7.1 优化目标（多目标 + 嵌套验证）
- 主指标：AUC ≥ 0.80、正召回 ≥ 0.90、负拒绝 ≥ 0.85、margin > 0（沿用交叉验证门槛）
- 优化目标函数 = 多指标加权（如 AUC + 正召回 + 负拒绝 + margin 的加权组合）
- **嵌套验证**：外层留一用户出最终指标；内层优化参数——避免"最优参数"在验证集虚高（过拟合）

### 7.2 变量空间分层
| 类型 | 变量 | 方法 |
|---|---|---|
| 连续 | group_weights（12 组含 motion）、relative_motion_weight、missing/各 missing 权重、软化参数（inside_scale / ramp_slope / 包络分位） | **贝叶斯优化**（Optuna / TPE） |
| 离散 | semantic_dtw 的 guard 开关（flower_opening / phase_order / jump_relation / short_core_capture 等 40+ 键） | 结构化搜索 / 逐项消融 |

### 7.3 约束
- 数据准入规则不变：用户 10/11 未审核、answer=2/3 永不进入优化数据
- 模板外用户验证是硬约束（同现交叉验证协议）
- 参数范围需语义合理（组权重非负、软化参数 ∈ 合理区间），避免数学最优但语义荒谬的解

### 7.4 时序依赖
1. 先等 **motion 动态特征 + 6 模板结构稳定**（当前 v4 打包验证中）
2. 再全局优化权重——**特征/模板结构变化会使旧权重参数失效，先固化结构再调参**
3. 优化结果写回 profile（v5 校准版）→ 前端重新打包 → 全量回归（frontend_cv + verify_group_scores）

### 7.5 预期收益
- 提升 margin（正负区分更稳）
- 减少对个别难例的依赖（参数更具泛化性）
- 每词最优权重组合可回溯（可解释性）

## 8. 轻量模型打分模块（v2.3 新增，主打分）

### 8.1 概述
- **目标**：用轻量深度学习模型替代手工特征工程打分，实现"语义动作级"细粒度评分（47 个核心语义动作程度分/词），纯前端 ONNX 推理。
- **定位**：互动学习**主打分模块**（result.score = 模型综合分）；DTW 并集打分降级为模型不可用时的兜底。
- 综合分 = 目标词核心语义动作程度加权（0-100），**无词判定干预**；综合练习建议聚焦最差语义动作（中英双语）。

### 8.2 数据与标签
- 正样本 930 条（21 词，user1-7 训练 / user8-9 跨人测试 159 条）
- **VL 软标签**：qwen3-vl-8b 逐样本标注语义动作完成程度 0-100（本词动作打分可靠）；鸡蛋/花经手部特写双图重标注校准（+30/+12）
- 增强：时间缩放/平移/高斯噪声（930→2790，仅训练用户副本）
- 异常负例飞轮：幅度异常/时序乱序/手部噪声 3 类破坏性增强（2790）+ VL 标注低分（20-30 vs 正样本 85-90）→ "离谱→低分"监督
- 特征：235 维/帧（7 组：pose 27 + 双手 63×2 + face 36 + 手形 19×2 + 双手关系 8），归一化 scale=max(肩宽,躯干)

### 8.3 架构与训练
```
输入 landmark 序列 (1×30×235) → BiLSTM 骨干 ×3（冻结）→ 47 语义动作头（程度+存在性）
```
- 参数量 1.19M；损失 MSE(程度)+0.3×BCE(存在性)；冻结骨干 + VL soft-label 蒸馏（corr 0.06→0.81）
- 词判定头（P1 骨干 98.11%）仅作可选诊断，不干预总分

### 8.4 效果（跨人 test user 08-09）
- 词判定 98.11%（BiLSTM）；语义动作 corr 0.81 / MAE 0.061；综合分 mean 0.85
- 鸡蛋 0.57→0.93、花 0.76→0.87（标签校准后）；前端加载 0.6s、打分 8-45ms

### 8.5 部署
- 模型文件 `apps/web/assets/model/`（action/word ONNX ~4.8MB + 双语 meta）；推理库 `vendor/onnxruntime/`
- 打分模块 `apps/web/js/model-scoring.js`（特征构建与训练逐位一致 + ONNX 推理 + 双语建议）
- 面板：语义动作彩色 bar（局部语义评分面板）+ 针对性指导（最差动作）；无模型小框
- 技术文档：`docs/scoring/sign_language_lightweight_model_scoring_20260809.md`（公开仓库）

### 8.6 已知限制
1. 动作头对"非本词样本"输出无监督偏高（分离度 0.006）——"做错词→低分"依赖门控（默认关）或负例训练

3. 下一步：异常负例接入训练、双监督架构（词判定依赖动作头）、魔塔 Static 部署

## 9. 语义动作级联打分模型 + 语义头门控（conf 门控）：用"目标词叶子激活度"拦截乱作/非目标词（v2.4 新增，术语 v2.6 与项目介绍面板统一）

### 9.1 背景与动机

- D6.2（全量 auto_score 增强数据训练）曾因 overall 虚高回退——乱作/负例也打出 86-87 分。根因：增强样本的 VL 分集中 85-87 无梯度，overall 头退化。
- 回退 D6.1（930 纯正例训练，现场 holdout MAE 4.92）后实测发现：**目标词叶子激活度天然就是"词判定"信号**——正例 conf 0.51-0.82，乱作负例 conf 0.003-0.034（间距 >10 倍）。
- 机制基础：47 个动作头是**独立 sigmoid 二分类**（非 softmax 路由），conf = 目标词叶子平均激活度 = 该词"被检测到"的置信度；训练标签只有目标叶子有值、其余 0，模型自然学到"目标叶子激活度 ≈ 词判定"。

### 9.2 门控公式（前端已实施，PR#96 合并）

```
conf        = mean(action_head[word_actions[word]])   # 目标词叶子平均激活度（0-1）
gate_factor = min(1, conf / 0.5)                      # 软门控：连续缩放，非硬开关
total       = overall × gate_factor × 100
```

- conf ≥ 0.5：不折减；conf < 0.5：按比例平滑压分（0.1 → 打 2 折）
- conf 不足提示词（中英双语）：conf < 0.1 强提示"未识别到核心语义动作，可能未做该词动作或双手未入画"；0.1-0.5 提示"识别不足，已折减"
- 实施点：`model-scoring-cascade.js`（CascadeScorer.score）+ `scoring.js` 主路径（gate:true）

### 9.3 门控验证（sample_collection 114 样本 = 66 正例 + 48 负例）

| 模型 | 正例 conf median | 负例 conf median | 正例 overall mean | 负例 overall mean |
|---|---|---|---|---|
| D6.1（930 正例） | 0.753 | 0.005 | 0.857 | 0.849 |
| D6.3（930+12486 增强混合） | 0.517 | 0.001 | 0.717 | 0.664 |
| D6.4.1（930+48 负例 Ov=0） | 0.322 | 0.003 | **0.292（崩）** | 0.041 |

阈值标定扫描（pos 折减 = 正例被误压比例，neg 拦截 = 乱作被正确拦截）：

| 模型 | 推荐阈值 | 负例拦截 | 正例折减 |
|---|---|---|---|
| D6.1 | 0.2（线上 0.5 可优化） | 44/48 (92%) | 13/66 (20%) |
| D6.3 | 0.1 | 45/48 (94%) | 12/66 (18%) |

- 漏网样本（两模型都拦不住 2 个：烤串 conf 0.92、超市 conf 0.90）——"不完美但动作对"，VL 也打 85 分，**不拦是正确的**
- 结论：conf 门控依赖阈值，但正负间距 >10 倍时阈值落在"无人区"，非临界敏感；更精细标定用 ROC/阈值扫描

### 9.4 D6.4 负例补充实验（进行中）

- **D6.4.1（已完成）**：930 正例 + 48 现场乱作 neg（A/Ov 全 0）训练 → best_overall_mae=0.0212（数据内 te）但**现场 overall 崩**（正例 mean 0.29）：Ov=0 标签对 5% 样本过强；且 48 条含 5 个"不完美但动作对"被错标 0。**结论：负例标签必须精细**。
- **D6.4.2（进行中）**：负例标签改为 VL 精细标注——渲染 8 帧骨架网格 → qwen3-vl-8b 判定 47 动作头激活度 + 21 词匹配度 + overall（每样本 3 次取均值，全局并发池 24 线程 ≈ 90s/48 条）。规则：47 动作头全未激活（max<15）→ overall 强制 0；否则取 VL 均值。脚本 `work/scripts/slu_neg_action_vl_label_v2.py`，输出 `work/generated/neg_action_vl_labels_v1_20260815.json`（**48 条完成：47 条有动作头标注、仅 1 条纯乱作全 0**——v3 prompt"描述引导+稀疏输出"修复了 v1 存在性判断过严的全 0 问题）。
- 训练配方：纯乱作 neg → A 全 0 + Ov=0；部分包含动作头 neg → A 用 VL 激活度 + Ov 用 VL 分。

### 9.5 词级门控豁免与镜像修复（2026-08-15~16 上线，PR#101/105/106）

- **词级豁免（PR#101）**：人们（人民）/汽车（二）conf 阈值=0（不设门控）。依据：两词为精细手形/少样本词（汽车二训练仅 39 条），D6.1 conf 对 pos/neg 无分离度（pos 0.006-0.16 vs neg 0.004-0.007 几乎重叠），全局门控误伤正例（1-28 分）；豁免后正例恢复 82-87 分。已知取舍：豁免词乱作负例可能虚高（86 分）。
- **镜像取 max（PR#105/106）**：原序列 + 左右手镜像序列各打分取高者，保证单手/惯用手左右对称。两个修复：
  1. **严格互换**（PR#105）：单手镜像不再"假变双手"（旧逻辑对侧为空时保留原位 landmark，镜像后两侧同一只手 → 特征失真）
  2. **数组兼容**（PR#106）：mirrorFlipPoints 用 p.x 取值，但浏览器 Holistic landmark 是数组 [x,y,z,vis,pres] → x 全变 1 → 镜像失效；修复为 Array.isArray 兼容（与 points3 一致）
- **验证**（新录 3 个"跳"样本，正手/反手）：正手（右手主）原序列 84 分；反手（左手主）原序列 0 分 → 镜像后 84 分；三样本 max 全 84 分，对称达成。
