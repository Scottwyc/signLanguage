## 本轮问题

实测发现 `花` 的得分在引入高能量动作窗口后反而变差，原因不是 `花` 应该只看局部窗口，而是评分时对“重要特征”与“无关特征”的区分还不够强。`花` 的语义重点是一手撮合后缓慢张开，脸、躯干、手相对躯干位置都不应主导距离。

同时，`跳` 不能按单手动作处理。资料文档明确说明：右手食指/中指模拟两条腿，左手模拟地面。因此 `跳` 是双手语义：右手为主动态手，左手为必要参照手，脸和躯干仍然为零或极小权重。

## 评分算法同步修正

本轮不仅修正数据库 profile，也同步修正评分距离，使权重能真正影响结果：

1. 缺失关键点惩罚改为按语义组加权，不再被 face/pose 等低权重组稀释。
2. 左右手互换匹配时加入缺失惩罚，避免把缺失的一侧错误判成更优匹配。
3. 手部主导 profile 会放大手部动态、手形动态和语义 delta 的影响。
4. `花` 等长流程/上下文敏感动作使用完整序列语义加权 DTW，同时保留 action-window 诊断。
5. `跳` 等短促动作使用语义高能量窗口 DTW，并对同一动作重提取、子采样和轻微时间采样噪声做保守补偿。
6. 短动作窗口不再强行叠加完整序列端点惩罚，避免开头/结尾静止帧影响关键动作。

## 后续固定规则

之后新增或修正任意样本时，都应先读取资料文档的动作说明，再设置数据库权重：

1. 先判断主语义是手形、手部轨迹、双手相对运动、脸/嘴、头部/pose，还是多阶段组合。
2. 只给文本语义明确要求的部位高权重；没有语义作用的脸、躯干和手-躯干相对位置应置零或低权重。
3. 对双手动作必须保留必要参照手，例如 `跳` 的左手地面。
4. 对单手动作允许左右手互换，但缺失和额外双手动作仍要有小权重约束。
5. 逐帧权重要由关键动态能量驱动，开头/结尾静止帧不能主导 DTW。
6. 每次 profile 更新后必须重跑模板审计，并把 `semantic_frame_weights.json` 写回对应模板目录。
