## 3. 采集交互优化

### 3.1 摄像头开关与权限提示

当前页面提供单按钮摄像头开关：

- 点击“开启摄像头”后调用浏览器 `getUserMedia`。
- 点击“关闭摄像头”会停止浏览器 `MediaStream` tracks，并禁用“采集并打分”。
- 摄像头异常时，前端按错误类型给出权限、设备占用、非 localhost 访问等提示。
- 浏览器只申请视频，不申请音频。

前端默认请求摄像头时倾向使用更高分辨率：

```javascript
width: { ideal: 960 },
height: { ideal: 720 },
facingMode: "user"
```

### 3.2 参考动作默认隐藏

“查看参考”按钮默认关闭参考视频，用户需要时再展开。这样做的目的有两个：

- 首屏优先展示用户自己的摄像头画面、采集参数和结果区。
- 避免参考视频长期占用宽度，导致采集按钮、日志和诊断信息被挤出可见区域。

目标词切换后，参考视频会同步切换到对应 demo。

### 3.3 采集前倒计时

点击“采集并打分”后，页面先显示 `3、2、1、开始` 倒计时，再正式采集。这个优化解决了用户点击按钮后还没摆好动作就开始录帧的问题，尤其对 `花` 这种需要从撮合到张开的动作更重要。

### 3.4 布局与首屏可用性

当前布局采用左侧宽采集区、右侧窄结果区：

- 左侧主视频区域更宽，便于用户确认手部是否入画。
- 右侧结果区压缩为信息面板，展示分数、DTW 指标、语义诊断和自动诊断。
- 隐藏参考视频时保持用户视频紧凑比例，避免画面过高。
- CSS 已加入窄屏响应式布局，移动或小窗口下会自动改为单列。

## 4. 采样质量优化

### 4.1 目标词动作重点提示

页面会根据目标词显示“动作重点”：

| 词条 | 前端提示重点 |
| --- | --- |
| `花` | 一只手从撮合到张开，手指绽放过程要清楚入画 |
| `跳` | 左手作为地面稳定入画，右手食指/中指在左手上方完成弹跳 |
| `香蕉` | 一手竖食指作为香蕉，另一手沿食指向下剥开 |
| `汽车` | 两手像握方向盘一样同步转动 |
| `唱歌` | 嘴巴张开，双手从喉部两侧向外移动 |

这部分属于采集引导，不改变评分逻辑，但能减少明显错误采集。

### 4.2 词条级采样下限

前端根据词条设置最低采样要求，并在用户设置过低时自动调整：

| 词条 | 推荐最少上传帧 | 最短采集时长 | 最低上传 FPS |
| --- | ---: | ---: | ---: |
| `花` | `12` | `2.5s` | `5` |
| `跳` | `6` | `2.0s` | `5` |
| 默认 | `10` | `2.5s` | `5` |

页面会显示“当前设置是否满足推荐”，如果不满足，会在采集时自动调整到推荐下限，避免 3-5 帧这类过短样本直接进入评分。

### 4.3 高频候选采集与运动能量选帧

当前前端不再只按上传 FPS 简单均匀抽帧，而是：

1. 先用更高频率采集候选帧。
2. 每帧计算低分辨率运动签名，当前签名网格为 `32 x 24`。
3. 根据相邻帧亮度变化估计运动能量。
4. 对运动能量做局部平滑。
5. 从候选帧中选择覆盖时段和运动峰值的上传帧。
6. 为上传帧生成 `frame_weights`，把动作更明显的帧传给后端作为时序权重参考。

这使前端可以兼顾两个目标：

- 保留起止阶段，不只上传运动峰值。
- 对关键动作帧增加权重，提高 `花` 张开过程、`跳` 弹跳过程被识别和对齐的机会。

### 4.4 上传 payload 增强

当前评分请求除了 `target_word/fps/duration_sec/frames` 之外，还会携带：

| 字段 | 用途 |
| --- | --- |
| `frame_indices` | 标记上传帧来自候选序列中的位置 |
| `frame_weights` | 表示帧级运动/覆盖权重 |
| `client_source` | 标记来源为 `browser_camera` |
| `client_session_id` | 浏览器本地会话 ID，便于追踪同一浏览器的连续复测 |
| `client_capture_id` | 本次采集 ID |
| `wait_for_ready_sec` | 允许前端请求等待后端 Holistic 初始化完成 |

浏览器上传的是 JPEG base64 帧，不上传完整视频文件，也不上传音频或浏览器 `MediaStream` 对象。

## 5. 结果区与可解释诊断优化

### 5.1 分数不再单独呈现

当前结果区除了圆环分数，还展示：

- `DTW distance`
- `normalized distance`
- Holistic 识别耗时
- 上传/识别帧数
- 分组平均距离
- 序列惩罚
- 语义诊断表

这样可以避免用户只看一个分数，不知道低分来自动作问题、采集问题还是语义不匹配。

### 5.2 采集质量状态

前端把后端返回的采集质量状态翻译为中文：

| 后端状态 | 前端显示 |
| --- | --- |
| `score_valid` | 可评分 |
| `needs_recapture` | 建议重采 |
| `semantic_mismatch` | 动作语义不足 |

分数圆环颜色也会随状态变化：可评分为正常色，建议重采为警告色，语义不足为错误色。

### 5.3 目标词级建议

前端根据目标词和后端诊断字段生成操作建议：

- `花`：提示撮合到张开的顺序、核心手覆盖、张开分数、是否更像双手交互动作。
- `跳`：提示左手地面和右手两指是否同时入画、相对运动方向、弹跳幅度和局部弹跳段。
- 其它词：提示保持关键手形、移动方向和动作起止完整入画。

这让前端从“给分页面”变成“可指导用户重采的练习页面”。

### 5.4 语义诊断表

当前语义诊断表已经展示多类内部字段，包括：

- 样本 ID
- 采集建议
- 采集状态与采集诊断
- 对齐策略
- 分数尺度原因
- 语义 floor 原因、来源和分数
- `跳` 的局部弹跳段帧范围、覆盖率和两指手形
- `花` 的张开分数和张开手
- 花/跳交叉检查结果、对照词分数和 margin
- 花-跳样混淆守卫
- 相位顺序守卫、锚点帧、乱序指标和触发项
- 左右手覆盖、必要覆盖惩罚

这些字段用于解释“为什么这次结果是可评分、建议重采或语义不足”，也便于后续用样本 ID 做离线回放。

### 5.5 样本 ID 追踪与复制

每次 `/api/score` 返回后，前端会显示 `request_id`，并提供复制按钮。后续排查时可以直接使用这个样本 ID 做定点回放，例如只诊断某一次用户复测，而不是重跑全部历史网页样本。

## 6. 自动诊断与复测闭环优化

### 6.1 自动诊断状态面板

右侧结果区新增“自动诊断”面板，用于展示 watcher 对 marker 后新增网页样本的诊断状态。前端读取路径为：

1. 优先读 `/api/watch-status`。
2. 如果后端接口不可用，回退到 `/static/watch_status.json`。

面板展示：

- watcher 当前事件
- marker 后新增目标样本数量
- 最后检查时间和状态新鲜度
- 目标完成度
- 缺失证据 gate
- 新增样本诊断结果
- 回归、语义诊断、交叉混淆、骨架可视化和前端契约报告链接

如果 watcher 状态超过 `90s` 没刷新，页面会提示监听状态可能过期。

### 6.2 复测轮次准备

页面提供“开始复测轮次”按钮。它会记录当前 marker 作为本轮起点，随后用户采集 `花/跳` 时，watcher 会根据 marker 后新增样本自动诊断。前端还会在用户完成 `花/跳` 打分后，按 `5s/25s/45s/75s/120s` 自动刷新诊断状态，减少手动刷新。

### 6.3 词条覆盖与下一步提示

前端根据 `browser_capture_evidence` 显示必需词条覆盖状态：

- `已覆盖`
- `缺失`
- `待采集`
- `需复查`

同时显示下一步提示，例如“采集 花、跳”或“复查 某词条”。这解决了复测时用户不知道还缺哪个词的问题。

### 6.4 前端契约检查展示

watcher 诊断后会写入 `frontend_contract_check`。前端会把契约检查是否通过、失败数量、报告/骨架链接可访问数量显示到自动诊断说明中。这样可以确认“自动诊断结果不仅生成了，而且浏览器能打开相应报告和可视化产物”。

## 8. 剩余限制

当前前端优化已经明显改善可用性和诊断闭环，但仍有几个边界需要保留：

1. 当前分数仍是 demo 模板原型相似度，不是正式真实用户评分。
2. 当前项目仍缺真实用户样本和人工评分标签，因此不能声明阈值、等级或合格线已经校准。
3. 自动诊断目标仍是 `NOT_READY`，因为 formal marker 后还缺真实网页摄像头 `花/跳` 双词样本。
4. 前端可以提示重采、增加采样质量和暴露诊断字段，但不能从根本上解决 MediaPipe 在遮挡、出画、强模糊时的识别失败。
5. 浏览器摄像头权限仍依赖 `http://127.0.0.1:5080` 或 `localhost` 安全上下文；远端裸 HTTP 地址通常不能直接申请摄像头权限。

## 9. 下一步建议

下一步建议按当前页面完成一次正式复测轮次：

1. 在页面点击“开始复测轮次”。
2. 分别采集 `花` 和 `跳`。
3. 等 watcher 自动诊断新增样本。
4. 查看页面自动诊断区的词条覆盖、下一步提示和报告链接。
5. 如果出现低分，复制样本 ID，用增量回放脚本做定点诊断。

只有 marker 后真实网页摄像头 `花/跳` 双词样本都通过自动诊断后，才能把前端真实复测闭环标记为完成。
