## 一、需求分析

### 1.1 核心需求

| 需求 | 说明 | 技术要点 |
|------|------|---------|
| **标准动作库** | 存储标准手语示范视频/特征 | 每个语义至少 3-5 个标准样本 |
| **实时采集** | 摄像头拍摄用户动作 | 低延迟，实时反馈 |
| **特征比对** | 用户特征 vs 标准特征 | 逐点/逐帧相似度计算 |
| **准确度评分** | 给出 0-100 分或等级 | 多维度评分（手势、时序、流畅度） |
| **错误定位** | 指出具体哪里不准确 | 关键帧/关键关节差异分析 |
| **孤立词场景** | 单个手语词评测 | 简化时序建模 |

### 1.2 与识别系统的差异

| 识别系统 | 评测系统（本方案） |
|---------|------------------|
| 目标：识别是哪个手语词 | 目标：评估动作准确度 |
| 输出：语义类别 + 置信度 | 输出：分数 + 错误分析 |
| 比对：特征向量整体相似度 | 比对：逐关节/逐帧差异 |
| 容错：允许一定偏差 | 敏感：需要检测偏差 |

## 二、技术路线评估

### 2.1 核心组件是否够用？

**结论：核心组件够用，需要增强评分和错误分析模块**

| 组件 | 状态 | 说明 |
|------|------|------|
| **MediaPipe Holistic** | ✅ 完全够用 | 543 个关键点足够精确描述动作 |
| **特征提取** | ✅ 够用 | 需要增加关键关节权重 |
| **FAISS 向量搜索** | ⚠️ 部分够用 | 整体相似度可用，但需要逐点比对补充 |
| **时序归一化** | ✅ 够用 | 插值到固定帧数适用 |
| **评分模块** | ❌ 需要新增 | 当前方案没有评分逻辑 |
| **错误分析** | ❌ 需要新增 | 需要定位具体差异 |

## 四、特征比对方法

### 4.1 整体相似度（快速粗评）

**原理**: 计算用户特征向量与标准特征向量的余弦相似度

**输入**: 
- 用户特征向量（D 维）
- 标准特征矩阵（N×D，N 个标准样本）

**输出**: 0-1 相似度分数（1 表示完全一致）

**特点**: 
- ✅ 快速，适合初筛
- ❌ 无法定位具体差异

### 4.2 逐关节差异分析（精确定位）

**原理**: 计算每个关节点（左手、右手、身体、面部）的平均欧氏距离

**输入**: 
- 用户特征序列（F 帧×543 点×3 坐标）
- 标准特征序列（F 帧×543 点×3 坐标）

**输出**: 各部位差异分数
- 左手差异
- 右手差异
- 身体差异
- 面部差异
- 整体差异

**特点**: 
- ✅ 可定位具体哪个部位不准确
- ✅ 支持细粒度反馈

### 4.3 DTW 时序对齐（处理速度差异）

**原理**: 动态时间规整（Dynamic Time Warping），处理用户动作速度与标准不一致的情况

**输入**: 
- 用户特征序列（T1 帧×D 维）
- 标准特征序列（T2 帧×D 维）

**输出**: 对齐后的距离分数

**特点**: 
- ✅ 处理动作快慢不一致
- ❌ 计算较慢

## 五、评分模型

### 5.1 综合评分公式

**评分维度及权重**:

| 维度 | 权重 | 说明 |
|------|------|------|
| **关节准确度** | 50% | 手势、肢体关键点的准确度 |
| **时序准确度** | 30% | 动作节奏、时序的准确度 |
| **速度准确度** | 20% | 动作速度的准确度 |

**分数计算**:

1. 各维度差异转换为分数（差异越小分数越高）
2. 加权平均得到总分
3. 根据总分评定等级

### 5.2 等级评定

| 分数范围 | 等级 |
|---------|------|
| 90-100 分 | 优秀 |
| 80-89 分 | 良好 |
| 60-79 分 | 及格 |
| 低于 60 分 | 不及格 |

### 5.3 错误反馈生成

**系统自动生成反馈报告，包括**:

**优点**:
- 指出做得好的部位（如"左手动作较为准确"）

**不足**:
- 指出偏差较大的部位（如"右手动作偏差较大"）

**改进建议**:
- 具体建议（如"注意右手手势，参考标准动作调整"）

**输出示例**:
```
手语：你好
准确度：85 分（良好）
整体相似度：0.87

详细分析:
  左手：差异 0.12
  右手：差异 0.08
  身体：差异 0.15

反馈:
  ✓ 右手动作较为准确
  ✗ 身体动作偏差较大
  → 建议：注意身体姿势，肩膀和手臂位置需调整
```

## 六、实施步骤

### 6.1 阶段 1：环境搭建（1-2 天）

**主要工作**:
- 创建 Python 虚拟环境
- 安装核心依赖（MediaPipe、OpenCV、FAISS、NumPy、SciPy 等）
- 验证安装是否成功

### 6.2 阶段 2：标准动作库建设（2-4 周）

**主要工作**:
- 确定目标手语词列表
- 录制标准动作视频（每人每个词 3-5 次）
- 多人录制（5-10 人，包含不同性别、年龄）
- 提取特征并存储

**录制规范**:
1. **场景**: 统一背景（如白墙），光照充足
2. **人物**: 多人录制，包含不同性别、年龄
3. **动作**: 每个手语词录制 5-10 次，包含速度变化
4. **格式**: MP4, 30 FPS, 分辨率 1280×720
5. **标注**: 文件名包含语义，如 `你好_张三_01.mp4`

**目录结构**:
```
standard_db/
├── features.npy          # 标准特征矩阵
├── metadata.json         # 元数据
├── videos/
│   ├── 你好/
│   │   ├── 你好_张三_01.mp4
│   │   ├── 你好_张三_02.mp4
│   │   └── ...
│   └── 谢谢/
└── ...
```

### 6.3 阶段 3：特征比对模块（2-3 天）

**主要工作**:
- 实现整体相似度计算
- 实现逐关节差异分析
- 实现 DTW 时序对齐（可选）
- 测试比对准确性

**模块功能**:
- 特征归一化
- 相似度计算（余弦、L2 距离）
- 关节差异统计
- DTW 时序对齐

### 6.4 阶段 4：评分与反馈模块（2-3 天）

**主要工作**:
- 实现综合评分算法
- 实现等级评定逻辑
- 实现错误反馈生成
- 调整评分权重

**模块功能**:
- 多维度评分计算
- 等级评定
- 优缺点分析
- 建议生成

### 6.5 阶段 5：实时评测系统（3-5 天）

**主要工作**:
- 摄像头视频流采集
- 实时特征提取
- 实时评分与反馈
- 可视化输出（骨架叠加 + 差异高亮）

**模块功能**:
- 摄像头采集
- 实时特征提取
- 实时评分
- 可视化渲染

### 6.6 阶段 6：优化与调优（持续）

**优化方向**:
- 评分模型优化（与人工评分对齐）
- 特征权重调整
- 实时性优化
- 用户界面优化

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| **评分与人工不一致** | 用户不信任 | 收集人工评分数据，校准模型 |
| **实时性不达标** | 用户体验差 | 优化算法，GPU 加速 |
| **标准样本不足** | 评分不准确 | 增加录制人数和次数 |
| **个体差异大** | 误判 | 引入自适应阈值 |

## 九、总结与建议

### 9.1 核心优势

1. **无需训练**: 基于规则，立即可用
2. **可解释**: 能指出具体哪里不准确
3. **易部署**: 纯 Python，无 GPU 依赖
4. **可扩展**: 后续可加深度学习优化
