# 手语动作准确度评测技术路线

**生成日期**：2026-04-23  
**版本**：v1  
**定位**：面向手语学习/训练场景的动作准确度评测系统  

## 1. 目标定义

本项目的核心不是“识别用户在说什么”，而是“评估用户做得像不像标准动作”。

系统输入为摄像头采集的视频流或本地录制视频，输出为：

- 目标手语词的匹配结果
- 0-100 分的准确度评分
- 分项评分，如手势、肢体、时序
- 错误定位与修改建议

当前阶段只做**孤立词**，不做连续语句翻译。

## 2. 技术路线总览

推荐路线是以 **MediaPipe Holistic** 为核心，先做可解释的关键点级评测，再逐步引入更强的时序建模。

```text
摄像头/视频
  -> MediaPipe Holistic 提取关键点
  -> 关键点清洗、归一化、时序对齐
  -> 标准动作库匹配
  -> 细粒度差异分析
  -> 评分与反馈输出
```

系统分两层：

- **MVP 层**：模板库 + 相似度检索 + 基础评分
- **增强层**：DTW 对齐 + 逐关节误差分析 + 错误定位

## 3. 为什么这样选

### 3.1 选择 MediaPipe 的原因

- 实时性好，CPU 可运行
- 同时覆盖手部、身体和面部关键点
- 对背景、光照变化比纯 RGB 方法更稳
- 适合快速搭建原型和后续扩展

### 3.2 不把 FAISS 当终点的原因

FAISS 适合做“找最像的模板”，不适合单独承担“准确度评测”。

更合理的方式是：

- FAISS 负责粗召回
- DTW 和逐点误差负责精排和评分
- 解释模块负责给出错误原因

### 3.3 不优先上 Transformer 的原因

Transformer、ST-GCN、3D CNN 适合后续提升上限，但当前项目的主要缺口不是模型容量，而是：

- 标准动作库如何定义
- 如何对齐不同速度的动作
- 如何把误差转成可读反馈

先把评测闭环做出来，再升级模型更稳。

## 4. 系统架构

```text
┌──────────────────────────────────────────────────────────────┐
│                     标准动作库                               │
│   每个语义 3-5 个标准样本，覆盖不同录制人和角度             │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│               MediaPipe Holistic 关键点提取                   │
│   手部、身体、面部关键点；统一到同一坐标系                   │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│           关键点预处理与时序标准化                             │
│   去噪、缺失补全、尺度归一化、固定帧数对齐                   │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│               粗匹配与精细比对                                 │
│   FAISS 召回 + DTW 对齐 + 逐关节差异分析                      │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│               评分与反馈输出                                   │
│   总分、分项分、等级、差异关节、纠错建议                       │
└──────────────────────────────────────────────────────────────┘
```

1. 标准动作库：每个语义保留 3-5 个标准样本，覆盖不同录制人和角度。
2. MediaPipe Holistic 关键点提取：提取手部、身体、面部关键点，并统一到同一坐标系。
3. 关键点预处理与时序标准化：进行去噪、缺失补全、尺度归一化和固定帧数对齐。
4. 粗匹配与精细比对：先用 FAISS 召回候选模板，再结合 DTW 对齐和逐关节差异分析。
5. 评分与反馈输出：输出总分、分项分、等级、差异关节和纠错建议。

## 5. 核心模块设计

### 5.1 标准动作库

标准动作库建议按“语义 -> 多模板”的方式组织。

每个语义至少保存：

- 3-5 个标准示范样本
- 样本录制者差异
- 样本录制角度差异
- 样本执行速度差异

建议保存内容：

- 原始视频
- 关键点序列
- 标注元数据

元数据至少包括：

- `semantic`
- `speaker_id`
- `view_angle`
- `speed_tag`
- `video_path`
- `feature_path`

### 5.2 特征表示

主特征建议优先使用关键点坐标，不要过早依赖 RGB。

推荐两级特征：

- **一级特征**：手部 + 身体关键点
- **二级特征**：加入面部关键点，用于表情相关场景

建议先把面部作为可选分支，而不是强行混进主特征，避免噪声干扰孤立词评测。

关键处理步骤：

- 坐标归一化
- 以肩膀或躯干作为参考系
- 统一左右手顺序
- 按固定帧数插值或采样

### 5.3 粗匹配

粗匹配用于快速筛选候选标准动作，建议使用：

- L2 距离
- 余弦相似度
- FAISS 向量检索

作用是找出最可能的标准模板，而不是直接给最终分数。

### 5.4 精细比对

精细比对负责评测核心结果，建议使用三类指标：

- **逐关节误差**：哪些点偏差最大
- **时序对齐误差**：动作快慢是否一致
- **关键帧误差**：起势、峰值、收势是否对齐

推荐引入 DTW，用来解决用户动作速度和标准样本速度不一致的问题。

### 5.5 评分模型

评分不建议只输出一个相似度，而是拆成分项再汇总：

- 手势准确度
- 肢体姿态准确度
- 时序一致性
- 流畅度

示例权重：

- 手势：50%
- 时序：30%
- 流畅度：20%

最终输出：

- `score`
- `grade`
- `part_scores`
- `top_errors`

## 6. 分阶段实施

### 阶段 1：MVP 原型

目标：跑通单词级评测闭环。

实现内容：

- MediaPipe 关键点提取
- 标准动作录制
- 特征保存与加载
- FAISS 粗检索
- 基础相似度评分

验收标准：

- 能录制至少 5 个手语词
- 能对单次输入返回候选结果和分数
- 能稳定实时运行

### 阶段 2：评测增强

目标：让分数更可信，反馈更具体。

实现内容：

- DTW 时序对齐
- 逐关节差异分析
- 分项评分
- 错误部位提示

验收标准：

- 能指出偏差较大的手部或姿态区域
- 同一动作快慢不同仍能给出接近的合理分数

### 阶段 3：模型升级

目标：提高上限，适应更复杂动作。

可选方向：

- LSTM/GRU 处理关键点序列
- Transformer 做时序建模
- ST-GCN 处理骨架图结构

这一步应建立在前两阶段已有稳定数据与评测规则之上。

## 7. 数据策略

### 7.1 采集原则

- 同一语义至少 3-5 个标准样本
- 不同人录制，降低个体偏差
- 不同角度、不同速度都要覆盖
- 记录失败样本，避免只保留“好看动作”

### 7.2 标注原则

建议给每个样本附加以下标签：

- 语义标签
- 录制人
- 角度
- 速度
- 是否完整
- 是否存在遮挡

### 7.3 数据量建议

如果只是 MVP：

- 5-10 个词
- 每个词 20-50 段视频或关键点序列

如果要做稳定评测：

- 20-50 个词起步
- 每个词至少 3 个标准模板

## 8. 风险与应对

### 风险 1：模板太少，结果不稳

应对：

- 增加标准样本数量
- 让不同人录制
- 引入模板集而不是单模板

### 风险 2：动作速度差异导致误判

应对：

- 采用 DTW 对齐
- 用关键帧对齐代替纯逐帧比对

### 风险 3：面部和身体噪声干扰结果

应对：

- 主体先用手部和姿态
- 面部分支独立建模
- 不把所有关键点强行压成一个特征

### 风险 4：评分缺乏解释性

应对：

- 分项评分
- 输出最差部位
- 输出关键帧差异

## 9. 推荐技术栈

### 基础层

- `Python`
- `OpenCV`
- `MediaPipe`
- `NumPy`

### 检索与对齐层

- `FAISS`
- `SciPy`
- `DTW` 相关库

### 后续模型层

- `PyTorch`
- `LSTM / Transformer / ST-GCN`

## 10. 推荐结论

当前最合适的路线不是直接做“高精度手语识别”，而是先做“可解释的手语动作准确度评测”。

最稳妥的落地顺序是：

1. `MediaPipe` 提取关键点
2. 标准动作库 + 模板管理
3. `FAISS` 做粗召回
4. `DTW` 和逐关节误差做精评
5. 输出评分、等级和纠错建议
6. 数据稳定后再上 `LSTM / Transformer / ST-GCN`

这样能同时满足：

- 快速出原型
- 结果可解释
- 后续可升级
