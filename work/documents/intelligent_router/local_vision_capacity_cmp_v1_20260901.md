## 三、关键结论

1. **两者都有原生视觉**（Qwen3.x GDN 视觉塔，与两个模型同架构），非 visionBridge 桥接——实测图像 token 确实进入（fig1 带图 prompt≈252/294 vs 纯文字 ~40）。
2. **基础能力（颜色/位置/OCR/计数/空间关系）均强且基本持平**：fig1/2/4 两模型全部答对。
3. **差异集中在"图表/精细数值读取"（fig3）**：**Qwen3.6-35B-A3B(35b) 完全宕机（空输出）**；**Qwen3.8-27B(27b) 有结构化推理但绝对数值上偏**。→ 两者都**不可靠**用于精确图表读数，但 27b 至少能给出"高低趋势+排序"，35b 直接无产出。
4. **风格差异**：35b 提问输出更直接简洁；27b 在需要推理的视觉题上**先写长 think 草稿再答**，导致正文易溢出被截断（与文本任务"思考超长"同源，非视觉特有）。
5. **⚠️ Qwen Code 前端注意**：settings.json 里 **Qwen3.6-35B-A3B(35b) 的模型注释为"工具调用可用"、未标"视觉可用"**；而 **Qwen3.8-27B(27b) 标了"视觉可用"**。即 Qwen Code 前端对 35b 可能不默认启用本地图像 pipeline（或走 visionBridge）。本测试是**绕过前端直打 API** 才测到真实多模态能力。**若成员要在 Qwen Code 里用 35b 看图，需先确认前端是否把该模型当视觉模型处理。**

## 四、建议分工（结合实测）

- **看真实图片/图/表格数据**：优先 **Qwen3.8-27B**（有推理趋势，读数需人工核对）；Qwen3.6-35B-A3B 看图**只能用于描述/OCR，不适合精确读图/读数**。
- **精确考据（图表数值、硬事实）**：仍建议走**联网核实**或 **deepseek-v4-flash-vision-exp（官方 API，顾问在用，1M ctx）**。
- **视觉作为 agentic 一环**：Qwen3.6-35B-A3B 有工具调用但视觉读取弱 → 若任务链里需"看图决定下一步"，用 Qwen3.8-27B 或官方 VL 更稳。
