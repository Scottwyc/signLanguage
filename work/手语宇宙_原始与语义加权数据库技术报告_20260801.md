# 工作汇报：手语宇宙原始与语义加权数据库

最后更新：2026-08-01 15:50 +0800

## 项目目标

基于 11 位志愿者、3 个视角和 21 个标准词汇的候选切割时间点，构建可追溯、可增量重建的原始 Holistic Landmark 数据库，并建立面向局部手语语义 DTW 的加权派生数据库。

## 当前工作进展

1. **切割候选已覆盖全部视频**：33 个长视频均已生成姿态静止边界和 Preview；32 个视频为 42 段，编号 11 左30°因源视频尾部截断仅有 40 段。

2. **原始 Landmark 数据库已完成**：共 21 词、1,384 个样本、45,310 个有效帧。标准应有 1,386 个样本，缺失 2 个均为编号 11 左30°源视频不存在的“指示”两次。

3. **数据库层次与可读性已统一**：词汇为顶层键，文件系统按“中文词汇/用户编号/视角/重复次数”组织；样本使用普通 JSON，可直接查看。坐标格式兼容历史 worker 的 `records[].result_data.*_landmarks`。

4. **Landmark Schema 已精简**：保存 Pose 33 点、左右手各 21 点、面部 12 个核心眼口点；不保存原始像素。Face 原始 ID 为 `[33,133,159,145,362,263,386,374,61,291,13,14]`。

5. **常驻 Holistic Worker 已用于全量构建**：5 个独立后端分别初始化 MediaPipe runtime，前端分发长视频任务。损坏帧采用连续解码、随机 seek 补读和受控跳帧；总缺帧率为 45/45,355，即 0.0992%。

6. **最新 21 词语义资料已解析**：DOCX 展示顺序与 A-Z 采集节点顺序分别保存，避免按文档顺序错误重标切片。

7. **汽车变体已锁定**：汽车（一）对应双手方向盘动作；汽车二对应单手车身前行动作。该映射由用户确认，并用多个视频的尾部密集帧复核。

8. **21 词语义加权 DTW 数据库已完成**：共 1,384 个派生分片和 45,310 个特征帧，固定特征维数为 Pose 27、左右手位置各 63、Face 36、左右手手形各 19、双手关系 8。

9. **缺失信息显式建模**：每个特征组同时保存固定维数值、mask 和 vector weights；Landmark 缺失时使用零向量和零 mask，不把缺失误当作真实零坐标。

10. **全量验证通过**：原始库和加权库验证错误均为 0。公开索引只包含编号、不含姓名；私有源路径与哈希单独存于 provenance manifest。

## 关键机制

1. **姿态归一化**：以肩中心为中心，以肩宽或躯干长度为尺度，减少用户位置和画面尺度差异。
2. **手形特征**：每手 19 维，包括腕到指尖距离、指间 spread、MCP 到指尖距离和手指伸直度。
3. **双手关系**：8 维描述双手基准点、指尖和手轴的相对关系。
4. **语义组权重**：每词单独分配 Pose、手位置、手形、Face 和缺失惩罚权重。
5. **关键点权重**：根据 DOCX 的实际动作语义对拇指、食指、指尖、肩部等局部点加权。
6. **阶段语义**：对牛奶、鸡蛋、科学、超市等多阶段词保存动作阶段顺序，供后续 phase-aware DTW 使用。
7. **主辅手适配**：原始左右手保持不变，评分阶段允许按惯用手或 best-of hand swap 归一化。

## 当前限制

1. 切割时间点仍属于待人工审核候选；人工修改后必须增量重建对应原始和加权分片。
2. 新增 11 词的权重来自 DOCX 文本到工程参数的映射，尚未用正负样本经验校准。
3. 编号 11 左30°源视频尾部缺失，无法补造“指示”两次样本。
4. 面部仅保留 12 个核心点，适合当前评分链，但不适合需要完整面部网格的其他任务。
5. 加权特征分片采用 `.json.gz` 机器缓存；其主索引、Profile 与 README 均为普通文件，可直接查看。

## 后续

1. 用户逐视频审核 Preview 和切割时间点，记录需修正的编号/视角/节点。
2. 根据修订的时间点按视频增量重建数据库，而不是全量重跑。
3. 构建每词同词正样本、异词负样本、错误动作样本，校准新增 11 词权重。
4. 验证跨用户、跨视角和主辅手镜像下的 DTW 分数分布。
5. 固定最终权重版本，生成可用于正式评分的发布候选数据库。
